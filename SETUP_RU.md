# Подготовка: сессия, резюме и личные настройки

Нужны Python 3.11+ на локальном компьютере и доступ к аккаунту соискателя hh. На сервере используется Docker: Playwright с headless Chromium либо SeleniumBase UC с полным Chrome и внутренним Xvfb. Desktop-приложение не устанавливается, видимое серверное окно не требуется.

## 1. Создать локальные файлы

Из корня проекта:

Если личные файлы уже созданы командой `configure init` в Docker, сохраните их и пропустите повторную инициализацию ниже. Локальное окружение всё равно нужно для первого входа и экспорта сессии.

```bash
python -m venv .venv
```

Активируйте окружение: Linux/macOS — `source .venv/bin/activate`, Windows PowerShell — `.venv\Scripts\Activate.ps1`. Если активация запрещена настройками PowerShell, используйте `.venv\Scripts\python.exe` вместо `python` в командах ниже.

```bash
python -m pip install -r requirements.txt
python -m playwright install chromium
python scripts/configure.py init --gender male --provider openai --model YOUR_MODEL
```

Замените `YOUR_MODEL` на доступное вам имя модели; `--gender female` включает женские формы. На PowerShell используется та же команда. Если подготовлены собственные файлы, добавьте их при первой инициализации:

```bash
python scripts/configure.py init --gender female --model YOUR_MODEL --profile "/path/to/my-profile.json" --competency-map "/path/to/my-cases.md"
```

Выберите один из вариантов инициализации. `init` заранее проверяет формат выбранных JSON/TOML и соответствие разделов Markdown проектам, затем атомарно копирует их в `hh-data/data/` и записывает относительные пути. Если файлы уже существуют, команда откажется менять их без `--overwrite`. Этот флаг создаёт конфигурацию заново, а не объединяет пользовательские фильтры; существующий `.env` сохраняется. Синтетические примеры не становятся фактами кандидата без явного подключения файла.

Локальную подготовку, особенно на Windows, выполните с движком по умолчанию `playwright`. После входа и выбора резюме можно включить `seleniumbase_uc` в копии конфига на Linux-сервере; команды инициализации для сервера также принимают `--browser-backend seleniumbase_uc`. Невидимый UC-режим с `headless = true` поддерживается на Linux через Xvfb; локально на Windows для этих шагов используйте Playwright. Смена движка не требует повторной инициализации профиля кандидата или выбора резюме.

В созданном `hh-data/.env` раскомментируйте и заполните ключ своего поставщика. Для OpenAI используется `OPENAI_API_KEY`, для другого OpenAI-совместимого API — `HH_AI_API_KEY`. Ключ не передаётся аргументом CLI и не выводится при проверке. Старый корневой `.env` поддерживается, но не нужен при выбранном варианте с `hh-data/.env`.

Пока оставьте `[schedule] enabled = false` и `[watch] robot_replies = false`.

Новый конфиг уже содержит ограничения темпа: минимум 180 секунд между попытками отправки откликов, серии по 2 попытки с паузой 25 минут, дневной лимит 10 по Москве и минимум 10 секунд между чтениями страниц. В дневной лимит входят подтверждённые отклики и попытки за сегодня с ещё неясной доставкой. Проверка роботов настроена на интервал 15 минут, до 10 открываемых чатов за цикл и 30 секунд между ответами. Обычная пауза откликов освобождает браузер для роботов; CAPTCHA приостанавливает все фоновые запросы к hh на 120 минут. Автоматические задачи включаются отдельно после проверки. Подробнее — [интервалы в конфиге](docs/CONFIGURATION.md#интервалы-и-ограничения-запросов).

Проверка без браузера, модели и изменений файлов:

```bash
python scripts/configure.py doctor
```

На свежей установке ошибки об отсутствующем ключе, сессии или резюме ожидаемы: команда перечисляет оставшиеся шаги и возвращает ненулевой код. Doctor показывает настроенный движок и политику интервалов, но не проверяет установку Chrome/Xvfb или доступность hh. Текущий срок возобновления после паузы показывает `server --status`. Если ключ хранится в старом корневом `.env`, укажите его явно: `python scripts/configure.py doctor --env-file .env`.

## 2. Войти через временный локальный браузер

```bash
python scripts/session.py login --config hh-data/config.server.toml
```

Откроется Chromium. Войдите в hh самостоятельно и дождитесь сообщения об экспорте сессии: после подтверждения браузер закроется. Бот не запрашивает и не сохраняет пароль или SMS-код. Если хотите использовать уже установленный браузер, добавьте `--channel chrome` или `--channel msedge`.

Проверенный вход записывается в `hh-data/data/hh-session.json`. Это секретный файл с данными авторизации; его передают только на свой сервер. Он переносится между ОС, в отличие от каталога браузерного профиля. hh может потребовать новый вход после смены IP или истечения сессии.

Затем восстановите проверенную сессию в локальный headless-профиль, особенно после повторного входа:

```bash
python scripts/session.py check --restore-session --config hh-data/config.server.toml
```

Для повторного экспорта уже действующего входа без видимого окна:

```bash
python scripts/session.py export --config hh-data/config.server.toml
```

## 3. Выбрать своё резюме

Команды ниже используют сохранённый вход в headless-режиме. Откликов, поднятия резюме и сообщений нет.

```bash
python scripts/resumes.py list --config hh-data/config.server.toml
python scripts/resumes.py select --id RESUME_ID --config hh-data/config.server.toml
python scripts/resumes.py fetch --config hh-data/config.server.toml
python scripts/configure.py doctor
```

Замените `RESUME_ID` на ID из списка. Одинаковые названия резюме различаются по ID. Команда `select` проверяет, что ID принадлежит вашему аккаунту, и сохраняет его в конфиге; остальные фильтры сохраняются. В режиме поиска по резюме обновляется и параметр `resume=` поисковой ссылки. `fetch` сохраняет текст вместе с идентификатором выбранного резюме. Чужой кэш для письма не используется.

За один запуск бот откликается по одному выбранному резюме.

## 4. Настроить поиск, факты и модель

Откройте `hh-data/config.server.toml` обычным текстовым редактором. Варианты поиска:

```toml
[search]
mode = "resume"  # suitable-вакансии выбранного резюме; select сформирует search_url
```

Или запросы по одной строке:

```toml
[search]
mode = "query"
query = """Python разработчик
Backend developer"""
```

Фильтры hh находятся в `[hh_filters]`, дополнительные исключения — в `[filters]`. Не включайте условие ГПХ, удалёнку или исключения профессий, если это не ваши требования. Полный справочник полей есть в `config.example.toml`.

Заполните [профиль компетенций, карту кейсов и настройки модели](docs/CONFIGURATION.md). Примеры профиля синтетические: перед подключением замените их своими подтверждёнными фактами.

Можно проверить генерацию письма отдельно:

```bash
python scripts/ai_test.py --config hh-data/config.server.toml --letter
```

Эта команда обращается к модели и может расходовать API-баланс, но ничего не отправляет в hh.

## 5. Перейти на сервер

Перед переносом остановите любые работающие экземпляры бота. Скопируйте код и личные файлы по SSH/SFTP либо соберите архив:

```bash
python scripts/package_server.py --with-private-data
```

Архив `hh-data/deploy/hh-bot-server.tar.gz` содержит секреты и историю. Не загружайте его в GitHub. Профили локального браузера в архив не входят. Для произвольных дополнительных файлов профиля используйте отдельный перенос по SSH: архив включает только явный список поддержанных имён.

Продолжение — [SERVER_RU.md](SERVER_RU.md).
