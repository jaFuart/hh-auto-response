# Ollama для серверного бота

Установите Ollama на отдельном компьютере или сервисе по инструкции её поставщика. Сначала проверьте, что выбранная модель установлена и доступна на машине Ollama (`ollama list`). В конфиге бота используются её фактическое имя и доступный с Linux-сервера адрес API.

```toml
[ai]
provider = "ollama"
base_url = "http://ollama:11434/v1"
model = "ИМЯ_УСТАНОВЛЕННОЙ_МОДЕЛИ"
api_key = ""
only_robot = true
```

Здесь `ollama` — пример имени сервиса в общей Docker-сети; штатный Compose этого проекта такой сервис не создаёт. Настройте свою общую сеть или укажите доступный адрес сервиса. `localhost` внутри контейнера — сам контейнер, а не локальный компьютер или хост Docker.

Ollama API не следует выставлять незащищённым в интернет. Для удалённой машины можно использовать частную сеть или SSH-туннель с привязкой к loopback, после чего обеспечить доступ к нему из контейнера. Сетевые параметры зависят от размещения сервиса.

```bash
docker compose -f docker/docker-compose.yml stop hh
docker compose -f docker/docker-compose.yml run --rm hh python /app/scripts/ai_test.py --config /data/config.server.toml --letter
```

Проверка вызывает модель, но не отправляет письмо в hh. Для писем и анкет нужна модель, способная следовать инструкциям и возвращать корректный JSON. Скорость и расход памяти зависят от модели и оборудования; программа не гарантирует одинаковую точность разных моделей.

Основные настройки: [CONFIGURATION.md](CONFIGURATION.md).
